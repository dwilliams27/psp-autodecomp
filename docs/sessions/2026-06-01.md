## Discipline — gaming HELD (byte-exact but rejected, not credited)

The north star is "what a respected matching-decomp project would do." These reached
0-diff only via codegen crutches with no genuine program semantics and were reverted:

- **eSimulatedController::GetPosition** (R9) — `__attribute__((naked))` 100%-asm body
  (hand `jr $ra`, hardcoded `$aN`, `.set noreorder`). Pure-assembly match.
- **gcPlayer::Reset** (R12) — `volatile int scratch; scratch = 0;` synthetic dead-store
  (meaningless local, emits a phantom `sw` to fake a byte).
- **eInputJoystick::GetIdleTime** (R15) — `volatile int best` local min-accumulator with
  no async semantics, load-bearing only as a stack-spill/non-CSE codegen lever.
- **eSimulatedState::Sleep** (R19) — `b->flags += 0;` no-op self-write, load-bearing only
  to emit a matching dead load/store.
- **eDynamicModel::Read / eShadowVolumeModelMtl::Read** (earlier this window) — `__asm__("ori %0,$0,1")`
  integer-MIPS constant-steering to materialize a C-expressible value.

Engine ban-list tightened to forbid these going forward (commit `2ad3f32`: naked bodies,
`ori`-constant seeds, synthetic volatile dead-store / no-op self-write crutches — even when
byte-exact). The legitimate near-miss outcome for an exact-size reg/sched residual is
`near_miss`, never a crutch.

## Tooling note — permuter false-EXACT

(R10 eDynamicAABBTreeAllocator::AllocNode via its internal harness; R11

when `compare_func --no-update-db` itself reports 0-diff.** The conductor enforced this all run.

## Residual unmatchable classes (genuinely resist honest source)

- **ADR-006 branch-likely divergence**, both directions (our SNC 1.2.7503.0 over- AND
  under-emits `bnezl`/`beqzl` vs the original) — e.g. cFile::Close, cGroup::RemoveAll,
  __rethrow, __can_throw_type.
- **Trailing-b-trap** — original appends a dead `b .; nop` (`0x1000ffff 0x0`) cold after the
  epilogue; no honest C construct emits it (eStaticMesh::Free, eRoom::Free, cFactory::DeleteGroups).
- **VFPU jr-delay-slot sink** — original fills `jr $ra` delay slot with the final `sv.q`;
  pspsnc-under-wibo can't schedule asm into it (eSimulatedController::GetVelocity/GetLocalToWorld).
- **TU-context register-allocation / frame-size (Mechanism-B)** — split-TU interference-graph
  tie-breaks differ from the original monolithic obj; small (2–44B) coloring residuals with
  no source leverage after permuter (many AssignCopy/Get*Index/Move near-misses).
- **va_start environment block** — `__builtin_stdarg_start` crashes pspsnc-under-wibo, so the
  unfolded masked vararg-pointer prologue is unreachable (sscanf, _open, fprintf, cStr/cFilename
  varargs ctors, cStrFormat/cStrAppend).

## Process

Every committed match: re-verified 0-diff with `compare_func --no-update-db` → asm-content
audit (reject/hold gaming) → `/pre-commit-review` (4-dimension, weighted for this domain) →
commit `src/*.cpp` + `config/functions.json` → `compare_func --update-db` credit → ff-merge
to `main` in ~3-round batches. Held results were removed (not committed); near-misses left as
untracked scratch.
