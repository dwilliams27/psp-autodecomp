## Assessment

The latest matching frontier has moved from generic low-hanging fruit to
repeatable failure modes. The last Opus runs were still productive, but the
failed tail now contains many rich notes that explicitly identify
register-allocation drift, cReadBlock prologue compiler behavior,
branch-direction/codegen divergence, and tagged-pointer shape issues.

The next system-level leverage is to classify failures once, feed that
classification into target generation, and generate richer per-target prep
packets for agents working larger or research-heavy functions.

## Plan

1. Add a reusable failure classifier for DB `failure_notes`.
2. Integrate classification into matching-prep reports and target generation.
3. Add a battle-packet renderer/CLI that packages target metadata, graph
   context, classifications, prior notes, matched exemplars, disassembly, and
   m2c output.
4. Keep the orchestrator path light by injecting concise failure
   classification into normal prompts, while leaving full battle packets as an
   explicit prep artifact.
