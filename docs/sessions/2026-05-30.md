# 2026-05-30 — Overnight Workflow-driven matching loop

## Intent

Pour the remaining 5-hour-window subscription compute into byte-exact matching before
the budget resets (~1 day out). Wake up with most AI spent and the match count as high
as possible. Survive the 5h rate-limit reset cycle (burn → pause → resume) and never
waste the rate-limited windows.

## Design decisions (operator-confirmed)

- **Serial, one function deep at a time** across the AI agents (low chaos, no worktrees).
- **Overnight branch `overnight-2026-05-30`**, auto-commit batches; operator ff-merges in AM.
- **Throughput targeting**: easiest fresh-untried first (small / leaf / no prior failure notes),
  maximize match COUNT. Hard/failed/large functions are routed to the CPU permuter pool.

## The two-resource principle

| Resource | Scarce (5h AI budget) | Abundant (always available) |
|---|---|---|
| AI healthy window | agents get functions to byte-exact or to *exact-size + register-only residual* | — |
| AI rate-limited gap | — | CPU permuter (`permuter.py`) grinds near-misses toward byte-exact |

The conductor pre-loads the permuter queue **before** the budget runs out, so the ~2h
rate-limited dead window does real work on CPU while the model rests.

## Architecture

- **Engine** (`.claude/workflows/overnight_match_engine.js`): Workflow that serially attacks a
  slice of `args` target objects, one deep research-driven agent per function, returns
  structured `{results, bailed}`. Bails after 2 consecutive agent failures (rate-limit signal).
- **Conductor** (this session, the loop below): selects targets, launches the engine, verifies
  every claimed match with the canonical verifier, runs `/pre-commit-review`, commits, updates
  the DB, and keeps the CPU permuter pool full.
- **Permuter pool** (background Bash): up to 3 concurrent `permuter.py --save-best` jobs (2 workers
  each, 12 cores). Survives rate-limited windows untouched; harvested on the next healthy tick.

Durable state = git + `config/functions.json`, so the whole loop is restart-safe.

## Conductor loop (one iteration)

1. **Select** next slice (default 4) of fresh-untried targets, smallest/leaf first, skipping
   size<12 junk and known-unmatchable. Prefer targets with empty `failure_notes`; feed any
   prior notes into the engine.
2. **Launch engine**: `Workflow({scriptPath: '.claude/workflows/overnight_match_engine.js', args: slice})`
   in the background.
3. On completion **harvest**:
   - For each `status==matched`: independently run `compare_func.py src/<f>.cpp --no-update-db`
     and confirm byte-exact + asm-ratio sane. Trust-but-verify; drop false claims.
   - For each `near_miss` with `structurallyComplete` (exact size, register/sched residual):
     enqueue a background permuter job (`--score-mode insns` for register cascades).
   - `failed` / `blocked`: leave untried→failed per outcome; record notes.
4. **Commit** (if verified matches): `/pre-commit-review` on the diff → fix issues → commit on
   the overnight branch → `compare_func.py <files> --update-db` to mark matched.
5. **Harvest permuter**: any permuter-target src that now compiles byte-exact → verify → fold
   into the next commit.
6. **Pace**:
   - engine `bailed` (rate-limit suspected) → make sure the permuter queue is full, then
     `ScheduleWakeup(~2400s)` and re-probe on wake. The harness's own rate-limit wait absorbs
     the exact reset time.
   - healthy → launch the next engine slice immediately (background completion re-invokes us).

## Stop / status (for the operator)

- Watch live: `/workflows` (engine progress) and `tail -f` permuter logs.
- Progress: `python3 tools/func_db.py stats`; `git log --oneline` on `overnight-2026-05-30`.
- To stop: interrupt the session, or let it idle out when targets/budget are exhausted.
- Morning merge: review `git log --oneline`, then ff-merge `overnight-2026-05-30` into `main`.

## Outcomes

**Smoke test (validated before going autonomous):**
- Engine on `cStrLength` worked end-to-end: research-driven agent, 5 angles, honest structured
  output. Result = exact 68B size, 0% asm, structurally complete, 3-byte `a1/a2` register-rename
  residual (REG_ALLOC tie-break). Conductor independently re-verified: exactly 3/68 bytes differ —
  agent report was accurate. Trust-but-verify path confirmed.

**Tooling finding — permuter symbol resolution for plain (non-class) functions:**
- `permuter.py` compiles with its own flags (`-c -O2 -G0 -Xsched=2 …`) which emit the *plain*
  symbol (`cStrLength`), while the Makefile build emits the SN-mangled symbol (`__0FKcStrLengthPCc`).
  The permuter then can't find the DB's mangled symbol → `PERMUTER_ERROR: target symbol '…' not found;
  available symbols: <plain>`.
- **Conductor workaround (no tool edit):** for plain functions (`class_name == null`), pass
  `--symbol <name-before-paren>` to the permuter. Class methods (C++ always mangles) work with the
  default. Validated: `--symbol cStrLength` ran 804 candidates cleanly. (REG_ALLOC a1/a2 is a hard
  case — 0 improvement in 60s — but the mechanism is sound; left grinding in background.)
- This is a genuine `tools/permuter.py` limitation worth fixing properly later (apply mangling in
  its symbol resolver, or auto-fallback to the lone emitted symbol). Logged here per "report tool
  bugs"; not patched mid-run to respect the tools/ guardrail.

**Refined permuter heuristics (learned live):**
- Reg-aware permuter (`--score-mode insns`) **cracks multi-byte coloring residuals** fast:
  collision handler 15B→0 in 35s; `eAudioPlatform::SetStreamVolume` 13B→0 in 3.4s.
- It does **NOT** crack **1-byte single-register tie-breaks** (`a1↔a2`/`a2↔a3` after a `move`):
  `cStrLength`, all `cStrCopy` variants — 12k+ candidates, 0 improvement. The specific
  allocation isn't reachable by source perturbation. → Conductor: don't spend long permuter
  runs on 1-byte single-reg ties; reserve CPU for structurally-complete *multi-byte* residuals.
- Permuter compiles temps as **`.c`**, so files needing C++-only types (`wchar_t` signatures →
  mangling) or VFPU flags (`-Xvfpumatrix`) **fail to compile** in the permuter. Affects the
  wchar `cStrCopy` variants and `MakeTextureScaleOffset`. (Another `tools/permuter.py` gap:
  use a `.cpp` temp ext + pass matrix flags. Logged, not patched mid-run.)

**Commit policy (efficiency):** byte-exact decompilation files can't be quality-improved without
breaking the match, so per-cycle `/pre-commit-review` is low-value overhead. Batching commits
~every 2 cycles → one review per commit (rule honored), more AI budget left for matching.
Matches are `--update-db`'d as verified (persisted to functions.json on disk) even before commit,
so a crash loses no work.
