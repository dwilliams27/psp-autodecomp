## Outcome: structurally complete, blocked by ADR-012 (REG_ALLOC)

The function is fully reconstructed. The residual is **pure context-dependent
register-allocation drift** (verified at instruction level): the inlined `gcDesiredValue`
release path lands the tagged handle in `$t1` where the original monolithic gcAll_psp.obj
TU used `$t0`, plus a matching `ori` tail-duplication, repeated across ~20 dances. That
de-aligns the body, inflating the raw diff to 4186/5640 despite identical structure. This
is exactly `docs/decisions/012-snc-context-dependent-regalloc.md` /
`docs/research/snc-register-allocation.md`: SNC's allocator carries state across functions
within a TU; our split TU gives different tie-breaks. No local source leverage exists.

Marked `failed` (category=REG_ALLOC). Source committed as the split-TU file
`src/gcDoEntitySpawn_operator_eq.cpp` (ODR-WARNING; does not touch the canonical file or
headers — the 6 existing matches in `src/gcDoEntitySpawn.cpp` reverify clean).

### New finding — the size lever

Declaring `unsigned int handle = t0;` as the first statement inside the `gcDesiredValue`
release guard (base still computed from `t0`, but the post-store null-test and vtable
deref reading `handle`) forces SNC to emit the original's handle-preserve move pair
(`move a2,a1 ; move a1,tN`) and brings the symbol to exactly 5640B. Without it SNC keeps
one copy in a high temp and the function is 88B short.
