## The headline finding — split-if/goto cracks the ADR-006 beqzl wall (MAJOR)

The dcast<T> / cType-cascade type-chain-walk null guard was being written as a **combined
`if (registered == 0 || t == 0)`** short-circuit, which SNC compiles to `beqz/bnez + nop`
and leaves an **8-byte ADR-006 "branch-likely" residual** (the original emits `bnez s2 / b /
beqzl a0`). This was previously classified as an unmatchable ADR-006 divergence.

**The fix: rewrite the parent-walk as a SPLIT-IF / GOTO form** mirroring the matched
`gcViewport`/`eVolume` siblings:
```c
T result = 0;
if (obj != 0) {
    cType *t = <gettype>;
    if (target == 0) {}
    else if (t != 0) {
        for (;;) {
            if (t == target) { result = (T)obj; break; }
            t = *(cType **)((char *)t + 0x1C);
            if (t == 0) goto nomatch;
        }
    } else { nomatch: result = 0; }
}
return result;
```
This reproduces the original's `beqzl` branch-likely exactly → **0 diff**. R8 retried 14
accumulated 8B near_misses and matched **14/14**; R10 matched the remaining 8 of 14 (the 6
fails were 400B 4-level, see below). This **overturns the ADR-006 "unmatchable" label for the
dcast/cType-cascade family** — they are matchable with the right source shape.

**Recommendation: fold this into `docs/decisions/006-bnel-compiler-divergence.md` and the dcast
recipe in the `matching-conductor` skill / `docs/research/snc-branch-likely.md`** — the
combined-`||` vs split-if/goto distinction is a general lever for SNC branch-likely emission,
not a per-function fluke.

## Verification method change — binary-authoritative slot check (asm/0.s is unreliable)

`compare_func` masks relocations, so a **wrong but masked D_<slot> still reports MATCH**
(the R6-class trap). The reliable cross-check is **binary-authoritative**:
- **Ordinal** (`ori rX, zero, IMM`) is a literal, NOT masked — uniquely identifies the
  registered type. Extract from `expected/bin/<addr>.bin` and compare to the source's outer
  `InitializeType` 3rd arg.
- **Slot address** = `(lui_imm << 16) + signed(lw_off)`, decoded from `expected/bin/<addr>.bin`.
  **`asm/0.s` MISLABELS slot addresses** — splat rounds the reloc target to the nearest
  symbol (e.g. it labelled `gcRegionSetGroup`'s real `D_00099AEC` guard as `D_00099AE8`).
- Plus: New-symbol reloc names the correct class; outer slot unique vs all committed dcasts.

This caught **2 masked wrong-slot bugs in R8** that an asm/0.s check missed (see reconciled).

## Yield map / lessons (what to do next session)

1. **Best byte ROI: gcAll dcast 2-3 level (280/340/348B)** — ~85-100% yield with the
   split-if form, ~10-15 min/round. **Now fully matched** (R1-R10).
2. **400B 4-level dcast family = ADR-012 coloring wall (unmatchable).** split-if fixes the
   beqzl, but the residual 8B is a saved-register **ascending-vs-descending coloring** divergence
   (original colors the parent-chain globals `s3/s4/s5` ascending by null-test order at depth
   4; our pspsnc keeps the depth-3 descending rule). Permuter + 8 source levers = 0 improvement.
   eAll/gcAll/gcDo* 400B 4-level all confirmed walled. Don't burn rounds here.
3. **cType-registration getters** (`gcConfiguration::Get{Core,Engine,Network}ConfigType`,
   `*::GetType`) **match via the dcast cascade recipe** — same `InitializeType` cascade +
   split-if. A clean vein when one exists (mostly exhausted now).
4. **gcDo* Evaluate (R3) and the regalloc/failed pool (R11) = low CLEAN yield** (~1/14 each):
   riddled with ADR-012 Mechanism-B coloring residuals; agents repeatedly reach for asm/trap
   crutches that must be caught. Poor bytes-per-hour; deprioritize.
5. **gcEntity accessors (R13) = mixed/hard** (2/14): exact-size Mechanism-B coloring drift.
6. **Genuine VFPU matches are fine** (R12 GetCollisionHandler 25%, ApplyPositionedForce 40%):
   constraint-bound `%N` ops with no scalar C equivalent (`vtfm3.t`/`vcrsp.t`/`vdot.t`/`sv.q`…),
   <50% by instruction count, per ADR-007. Audited clean.
7. **Shared parent cType slots are legit, not collisions** — `D_000385DC` (cBase),
   `D_000385E0` (cNamed), `D_00040C94`, `D_0009F43C` (gcEntityGeomConfig) are referenced by
   many sibling dcasts as base/middle levels by design. The uniqueness check must scope to the
   **outer/own** slot only.
