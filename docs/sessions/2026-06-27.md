# Session 2026-06-27 — sink sub-tenant integration (infra, not matching)

**Author:** Claude Opus 4.8. Operator (David) asked: "run overnight psp-decomp sessions
inside of sink" — i.e. bring psp's overnight harness under the mini's sink tenancy (kill
switch, subscription-only, uid isolation), without throwing away `orchestrator.py`.

## What this session did

Not a matching run — a tooling/infra session. psp now has a **sink-mode entrypoint** and is
declared as a nix-managed sub-tenant on the mini. The substrate (uid, PF anchor, `psp-run`
command, agenix PAT, kill-switch reap) lives in David's assistant repo; this repo gets:

- **`tools/run_sink.sh`** — the workload half. Sibling of `run_overnight.sh`, but: runs the
  orchestrator directly (already inside the PF jail, as `autodecomp`), **refuses to start if
  `OPENAI_API_KEY` is set** (subscription compute only — sink decision 0002), syncs `main`,
  runs the same preflights (`make prepare-read-prologue-compiler`, `verify_matches`,
  `verify_tree_compiles`), self-logs to `~/psp-sink-logs/`, writes a `run-status.json`
  breadcrumb, and unlocks the login keychain best-effort (Claude OAuth). `--push` optionally
  backs the `overnight/<ts>` branch up to origin (default local-only). The orchestrator
  itself still creates the branch and commits — unchanged.
- **`tools/sandbox_setup.sh`** — added a guard so it **refuses to run on the mini** (where
  the account + PF anchor are nix-managed; its uid-599/`staff` user creation would conflict).
  Laptop-only now.
- **`docs/decisions/015-sink-tenancy-subscription-only.md`** — the decision record.
- **`CLAUDE.md`/`AGENTS.md`** — a "Sink tenancy (overnight on the mini)" subsection (mirror
  kept identical).

## Design notes / why

- **Own uid, not `_sink`.** psp is private + carries the ISO/toolchain + its own PAT; folding
  it under `_sink` (public-repo sessions on the open web) would cross a trust boundary.
- **Trust boundary.** The repo checkout on the mini is `autodecomp`-writable, so the one root
  action (PF jail) lives in the nix-store `psp-run`, and the PF rules are nix-managed — never
  in this checkout. Only `run_sink.sh` runs from the checkout, strictly as `autodecomp`.

## Process

Spawned 4 adversarial reviewers (security, nix-eval, shell, ops) + a pre-commit verifier
before committing. They caught real bugs that are now fixed: the `set -e`/`ORCH_RC` capture
(was silently disabling `--push` on any failed run), the "file-based, no keychain" overclaim
(corrected — keychain unlocked best-effort), and the substrate-side switch-breakers (handled
in the assistant repo).
